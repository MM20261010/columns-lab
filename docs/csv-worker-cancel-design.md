# CSV処理の中断・復旧設計（Draft、2026-10-12 JST）

文書だけの独立Draft PRとしてレビューする。Workerコード、CSP、本番配信、公開設定はまだ変更しない。PR #3の保守的数式保護とPR #4の上限/保存後段を統合してから実装する。新しい権限・サービス・依存・Secrets・追加費用は不要の設計。

## 判断の理由

PR #4の区切り判定は完全レコードを探し、3候補を試験解析した後に本解析する。5万ASCII文字の引用セル1つ＋ヘッダーの局所計測では手動指定1回/50,007ループ/2セル、自動4回/200,028ループ/8セル。終了heap増分1.62/6.24MiB、5.63/30.46ms（各1回、計測用カウンター挿入、Work Node、ピーク/スマホではない）。検出走査自体も別にある。中途半端な引用レコードで切ると判定が壊れるため、雑な文字数打切りで直さない。

現状は解析/結合/CSV化がUIスレッド上の同期処理。Promiseやキャンセルフラグだけでは長いループ中にクリックを処理できない。手動の区切り指定は試験解析を省ける暫定策だが、主解析中の中断にはならない。レスポンスと中断を目的にDedicated Workerを第一候補とする。WorkerだけではピークRAMを削減する保証はない。

## メッセージと責務

- UI→Worker: 固定形式start（jobId、File配列、encoding/delimiter/source/skipBlank等の設定スナップショット）。CSVをURL、解析イベント、外部サービス、ログへ送らない。生のファイル名をエラー通信/計測へ入れない。
- Worker: Fileを読み込み、復号、区切り判定、解析、入力予算、結合前見積もり、結合、CSV化/Blobを実行。PR #4上限を維持。進捗は段階と数だけで、CSV本文/列名/ファイル名をログにしない。
- Worker→UI: jobId付きの段階進捗、少量のプレビュー（最大12行）、必要な診断情報、最後にBlob。巨大な入力/密な全行配列をUIへ返さない。Blobの複製やRAMへの影響は実ブラウザーで確認し、無コピーとは主張しない。
- UI: DOMはtextContent等で描画、Object URLとダウンロードリンクを管理。CSV/Blob生成後でもユーザーの保存操作を待つ。遅延した古い結果はjobId照合で無条件に破棄し、保存ボタンを有効にしない。

## 中断・失敗・再試行

1. 実行時に旧結果とURLを無効化。新jobId、新Workerを作り、設定変更・二重実行を制御する。キャンセルボタンだけは操作可能にする。
2. キャンセルまたは入力変更でjobIdを失効、UIからworker.terminateを呼び、参照を解放。Worker内finallyに後片付けを任せない。UIが持つURL/リンクはUI側で解放を試みる。RAM即時回収は保証しない。
3. error/messageerror/不正メッセージ/Worker生成失敗は固定の一般案内と保存無効化。プラットフォーム例外をそのままログ/解析へ送らない。
4. 再実行は新Workerで開始。古いmessage/onerrorは無視し、UIが実行可能な状態に戻ることを確認。キャンセル完了とCSV保存完了を混同しない。
5. Worker非対応/ブロック時に重い同期処理へ黙って戻さない。小さいデータと手動区切りの案内、または実行停止とする。軽いフォールバックの可否は明示的な仕様判断。

## 最小限の合格条件と残る設計事項

- 同じ架空入力が現行の局所統合案と同じCSV値/列順/ON保護/BOMを返す。文字コード/壊れたCSV/行セル文字数上限も維持する。
- 無害な長いセルと多数の短い行を、小さい段階から試す。解析/結合/CSV化中のキャンセルでUIが戻り、古い結果を保存できず再試行できる。意図的クラッシュ/資源不足は作らない。
- Blob/URL/保存リンク失敗とWorker error/messageerrorを注入して、一般案内、結果無効化、後片付けの試行を確認。
- Android実機で操作、回転、保存、キャンセル/再試行を確認。実測なしに「全端末で即時」「フリーズ防止」「安全RAM上限」と宣伝しない。
- 自動区切りの全候補解析を今後の別最適化対象とする。引用符・引用改行・長いレコードの意味を変えず、候補のスコア計算をレコード走査から得る案を比較。推測だけのセル長/サンプル上限を追加しない。
- 同一オリジンのローカルWorkerファイルとcoreのみを使う。CSP Report-Only計画のworker-src/script-src、Analytics互換性を事前確認。外部worker、eval、Service Worker、バックグラウンド同期を追加しない。

公式根拠: https://developer.mozilla.org/en-US/docs/Web/API/Worker/terminate （中断時にWorker自身の終了処理を待たない）。https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Using_web_workers 。これらのAPI説明と、当サイトの実装検証は別。

## Androidで未公開コードを試す方法（提案、未実施）

第一候補はオフラインの自己完結HTML。承認前のCloudflareプレビュー、外部ホスティング、LAN公開を使わない。

1. 固定したPR #3/#4のheadを取得し、レビュー済みの局所統合だけを1つのHTMLへ埋め込む。CSS/JS同梱、相対資産・外部リンク・Analyticsを外す。冒頭に検証用/未公開、元head、合成手順、SHA-256を記載。site配下に置かない。
2. ネット接続が必要なスクリプトを含まないことを確認。オフライン版限定のCSPでconnect-src 'none'、外部資産禁止とする。埋込スクリプトの許可方式は専用版だけに適用し、本番CSPを緩めない。Worker版を作る場合はfile/content URLでの対応を別確認する。
3. 本人がHTMLをAndroidへダウンロードし、機内モード（Wi-FiもOFF）でFennecから開く。Androidのfile/content URL制約で開けない場合、権限/セキュリティを緩めず停止。公開プレビューを代わりに無断作成しない。
4. 架空サンプルから始め、表示/回転/4行・5列・金額1,000の検算/保存/設定変更後の旧結果保存不可を確認。CSVは小さい架空2ファイルだけ。実データを使わない。
5. 長いセルは1万文字程度から、短い行は100→1,000程度から始める。固まり始めたら増やさない。上限・キャンセル機能の表示と実動作を区別し、Worker未実装の版で中断できると扱わない。
6. 記録はAndroid/Fennec版、元head、件数/設定、成功/失敗・応答性だけ。CSV本文/ファイル名/列名を解析や外部ログへ送らない。スクリーンショットも架空データだけ。

今回オフラインHTMLを配布/実機試験していない。file URLが使えない場合の代替は、本人が承認するアクセス制限付き一時検証環境などを別途比較する。新規接続/権限/公開設定が必要なら、準備してリスクを説明し承認を待つ。
