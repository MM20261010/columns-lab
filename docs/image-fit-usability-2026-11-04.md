# 画像サイズ合わせ：仕上がり寸法の誤解を防ぐ改善

## 問題と受入条件

本人の実機報告では、100KB以下・最小幅100px・最小高さ100pxで1280×681px / 85,625バイトのJPEGができた。これは旧仕様上は正しいが、本人は100×100pxになると理解した。実際の入力画像を受け取っておらず、同じ画像での再現試験ではない。

- 容量を優先する既存操作を保ち、「最小」は下限であることを明記する。
- 「仕上がり寸法を指定」では、幅・高さの双方が指定値と一致し、かつ容量の上下限を満たす場合だけ保存できる。
- 容量に収まらなくても、仕上がり寸法を黙って縮小しない。探索失敗と数学的に実現不可能な条件を混同しない。
- 設定変更後の旧結果の保存は禁止する。元画像は変更せず、画像・ファイル名を外部送信しない。

## 実装の優先順と今回の範囲

1. 最優先：指定方法の分離、確定寸法と容量の同時検証、全設定変更時の保存無効化。
2. 次：縦横比が異なる場合の扱い。初期値は白余白で全体を保持。中央切り抜きは周囲が欠け、引き伸ばしは形がゆがむと選択肢に明記。
3. 次：容量優先モードの最小・最大寸法を折りたたみへ。最小＝以上、最大＝以下。仕上がり指定とは別扱い。最大指定時は明示的に範囲内へ縮小し、拡大しない。
4. 表示：生成前に仕上がりの幅・高さ、選択方法、寸法を固定する旨を表示。容量優先では100px以上と100pxぴったりの違いを表示。スマートフォン向け既存1列レイアウト、最小44px操作領域を維持。

1〜4を今回実装。切り抜き位置ドラッグ、背景色選択、AI補間、バッチ、印刷単位、形式追加などは行わない。仕上がり指定では拡大もできるが、画質が粗くなる可能性を常時案内する。2,000万画素・各辺12,000pxの出力制限を適用する。JPEGの段階的品質探索、下限の水増し禁止、同意・目視確認後の保存を維持。

操作例：容量100KB以下 → 寸法の指定方法「仕上がり寸法を指定」 → 幅100・高さ100 → 白い余白（初期値） → 画像選択 → 変換確認 → 作成 → 見た目の確認 → 保存。
