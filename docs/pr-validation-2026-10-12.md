## PR #3：不可視接頭文字と負数

検証後head: bef19e5a78ac65159e91a26d3026738f60486bf8。今回変更はtests/formula-review.test.jsの追加確認とsite/tools/csv-merge/index.htmlの負数・型・桁数説明のみ。sanitizeForExcelの仕様は今回変えていない。

20接頭文字を調査: U+00AD/034F/061C/180E/200B/200C/200D/200E/200F/202A/202B/202C/202D/202E/2060/2066/2067/2068/2069/FEFF。各々の直後に半角または全角の無害な式開始文字を置く。現行検出はFEFFだけで、残る19接頭文字の後の式開始文字は無変更。OFFのCSV往復では元の文字列を保持した。分類テストは検出範囲の証拠であり、未検出値の安全性証明ではない。

LibreOffice環境はLibreOfficeDev 26.8.0.0.alpha0（2c87e51eeaa2b413ff4ae097b2705eea1995d8e5）だけ。Excel・通常版LibreOffice・GUI既定取り込み・他ロケールは利用可能な検証環境がなく未検証。インストールやアカウント追加はしていない。

開発版の限定試験は、普通の無害な式1件、20接頭文字×半角/全角の40件、負数8件の計49件。外部参照、DDE、ネットワークを伴う式や実データを使わない。入力CSVはローカルだけ、公開GitHubへ登録しない。ODSのformula属性・型・値を検査し、ログはケース識別子と集計値だけ。

- 入力フィルター: `Text - txt - csv (StarCalc):44,34,76,1,,0,false,true,true,false,false,0,true`。式取り込み有効、引用した項目を強制テキスト化しない。
- RAWは普通の式1セルにformula属性、40不可視接頭ケースには0。PR #3の保護ONは49件で0。ONをCSVへ再保存、同じフィルターで再取り込み後も0。RAWの再保存は計算値を書き出したため再取り込みでは0となる。RAWの再取り込み0を「元の式が安全だった」と誤認しない。
- 負数8件（-001、-000.50、-0、-.5、-1.、精度を超える整数2件、非常に大きい指数）: PR #3 ONではCSV文字列をそのまま保持するが、上記取り込み後の型は8件ともfloat。再保存した8件は元の字句表記と不一致。大きい整数2件と指数1件は格納された数値も元の十進数と一致しなかった。取り込み側の型・精度の影響であり、CSVを書き出す時点の値保持とは別。
- 従来のON処理は負数にもアポストロフィを付ける。開発版では8件ともstringになり、再保存でもアポストロフィ込みの元の文字列を保持した。PR #3では文字列扱いから数値扱いへ変わり得る重要な互換性変更。数値列には便利でも、識別子・先頭ゼロ・正確な長い桁には不適切になり得る。
- 列をTextとして指定した対照試験（token 5を1/2/2/2へ変更）は49件のformula属性0、負数8件はstring、再保存した負数の字句を8件とも保持。同じ再保存CSVを標準型・式取り込み有効で開き直すと普通の式1セルにformula属性が再び付いた（RAWをText指定した対照であり、PR #3 ON出力ではない）。次の取り込みでも型を指定する必要があり、永続的な保護とは主張しない。

判断: 不可視文字を削除・trim・NFKCして値を変える修正はしない。先頭の特定不可視文字＋式開始だけを保護する拡張は候補だが、開発版の観測だけでExcelの解釈を推測して全面変更しない。Excel/通常版Calcでの結果、保護範囲、負数仕様の互換性を公開前に判断する。万能な数式防止とは記載しない。

## PR #4：パイプラインと保存後段

検証後head: ec6411f0f881f0f2924a679f6042c36051f710f3。今回はsite/assets/app.jsの保存後段を修正し、tests/download-review.test.js、tests/pipeline-profile.jsを追加。

| 段階 | 保持・負荷と残る課題 |
| --- | --- |
| 読み込み | File.arrayBufferで全体を確保。入力10MiB/合計25MiBの既存制限はあるがストリーミングではない |
| 復号 | TextDecoderが全文文字列を作る。UTF-8失敗時のShift_JIS再試行もある。今回の段階別計測はUTF-8のみ |
| 区切り判定 | 完全なレコードまで走査し、最大3候補の試験解析。長い単一レコードでは少量サンプルにならず、後続解析と重複する。試験解析は合計残セル予算とは独立 |
| 解析 | セル/行の上限はあるが、1セル文字列の連結は完了前に進む。解析済みの前ファイルも保持する |
| 結合 | 元配列、フィルターした行参照、見積もり、密な結果を保持。出力膨張は結果配列の生成前に拒否するが、解析済みメモリを遡って削減しない |
| CSV化 | 行のmap、引用符処理、各行文字列と最後のjoin。入力/結果/CSVが同時に存在する。4百万UTF-16文字はRAMやUTF-8バイトの上限ではない |
| Blob/URL | UTF-8バイトとBOM、ブラウザーの内部ストレージが追加され得る。URL解放要求が即時RAM回収を保証するわけではない |

保存後段の修正: Blob、createObjectURL、a要素作成/追加/clickをtry/catchで包む。失敗時はlast=null、保存無効化、一般的な復旧案内。プラットフォーム例外・CSV本文・ファイル名をログへ送らない。生成済みURLは失敗時に即時revoke、click開始後は従来どおり1.2秒後にrevokeを試みる。要素削除/URL解放/タイマーの例外は後片付けを妨げないよう扱う。

成功＋8箇所の失敗注入（Blob/URL/要素作成/追加/click/要素削除/revoke/タイマー）を確認。古い結果の再保存不可、再結合への復旧、BOM/Blobバイト数、後片付けの試行を検証。remove/revoke自体が失敗したときの完全な解放は保証しない。これはVMでのAPI失敗注入であり、実ブラウザーの保存完了・OSへの書き込み・メモリ不足を実現した試験ではない。click成功から保存完了を判定することもできない。

### 正常なCSVへの影響とWorker案

2万5千行×19列の入力は合計475038セルで入力制限内。元ファイル名ONの出力はヘッダー込み500020セルで拒否、OFFは475019セルで成功する。通常の業務CSVでも、わずかな超過や保守的な文字数見積もりで拒否され得る。必要なら元ファイル名をOFF、不要列の削減/ファイル分割を案内するが、勝手な列削除や切り捨てはしない。実需要とスマホ結果がないため、暫定上限を安易に上げない。

判断: 同期処理中の即時キャンセルは既存PRでは未実装。区切り判定・解析・結合・CSV化をDedicated Workerへ移し、FileをWorker内で読み、入力変更/キャンセル時にworker.terminate、job IDで古い結果を破棄する別案を推奨。終了・再試行・文字コード・上限・元ファイル/名前の非送信を回帰試験する。WorkerにしてもピークRAMは保証されず、配列/文字列を大量コピーしてUIへ返さない設計が必要。依存追加・サービス・権限・課金は不要の案だが、今回コードへ導入していない。CSPのworker-src互換性も別途確認する。
