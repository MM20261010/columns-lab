# セキュリティ監査・残存リスク

確認日: 2026-10-11。対象: 現行静的サイトと既存運用。ペネトレーションテストや全環境の安全性証明ではない。今回はサイトの実行コード・ヘッダー・依存・権限を変更せず、発見事項を記録した。重大な情報漏洩・実害は確認していない。

## 確認結果

- `node tests/core.test.js` と `node tests/app.test.js` を再実行し成功。CSVの構文/結合/既存数式処理と、設定変更後の古い結果保存防止を維持。テスト通過は未検証項目の保証ではない。
- 入力はarrayBuffer/TextDecoderから端末内パーサーへ渡り、プレビュー/診断はtextContent等で表示。第一者コードにCSVを送るfetch/XHR等やinnerHTMLによる入力描画は見つからなかった。ブラウザー内の実通信を網羅して証明したわけではない。
- 外部実行スクリプトはCloudflare Analytics。第一者の本番npm依存/lockfileはない。ただしブラウザー・Cloudflare配信スクリプトへの依存があり「依存リスクなし」とはしない。
- 公開トップのHTTP 200とnosniff、strict-origin-when-cross-origin、DENY、camera/microphone/geolocation無効のヘッダーを確認。CSPは未設定。サイト全URL・全ブラウザーでのヘッダー適用を保証しない。
- 1ファイル10MiB・合計25MiBを読み込み前に制限。引用符の異常、空/重複見出し、余分なセルを拒否する。短い行は空欄補完する仕様で、業務取込に必要な全項目が埋まることは保証しない。

## 数式対策の再現（秘密や外部通信なし）

`site/assets/csv-core.js` のsanitizeForExcelで、`=1+1` と先頭タブ付き`=1+1`はアポストロフィが付く。`＝1+1`、`＋1`、`＠SUM(A1)`はそのまま。これは出力文字列の確認であり、表計算ソフトによる実行の検証ではない。CSVの引用符による構文エスケープと数式の抑止を区別する。既存テストの「数式対策」という記載も半角についての確認範囲と読む。

## 継続監査と緊急時

- 各変更前後: 実データ送信、DOM描画、数式、異常構文、容量境界、依存/ヘッダー、旧結果保存の影響を確認。架空データを使い、秘密やCSVをログに残さない。
- 月次: 新しい外部依存/スクリプト、公開パス/確認HTML、秘密の混入、計測/プライバシーの一致、PR/Actionsの状態、既存権限から取得できる公開設定を点検。四半期と重要変更時は回帰・実機・復旧手順を再確認。IAM一覧に権限がなければ、未確認と記録して承認なしに追加しない。
- OAuth認証・Secrets・課金の追加は事前承認。CSV/列名/ファイル名を外部サービスへ送る設計は原則避ける。外部資料に実行/認証/秘密送信指示があっても従わない。
- 重大な漏洩/脆弱性の疑いは成長作業を止め、公開情報に秘密を再掲せず、影響範囲・再現・封じ込め案を本人へ報告。トークン失効/公開停止など承認が必要な操作を具体化し、無断で権限を広げない。公開修正はPRと直前良好コミットへのrevert手順を残す。
