# セキュリティ監査・残存リスク

確認日: 2026-10-11。対象: 現行静的サイトと既存運用。ペネトレーションテストや全環境の安全性証明ではない。今回はサイトの実行コード・ヘッダー・依存・権限を変更せず、発見事項を記録した。重大な情報漏洩・実害は確認していない。

## 確認結果

- `node tests/core.test.js` と `node tests/app.test.js` を再実行し成功。CSVの構文/結合/既存数式処理と、設定変更後の古い結果保存防止を維持。テスト通過は未検証項目の保証ではない。
- 入力はarrayBuffer/TextDecoderから端末内パーサーへ渡り、プレビュー/診断はtextContent等で表示。第一者コードにCSVを送るfetch/XHR等やinnerHTMLによる入力描画は見つからなかった。ブラウザー内の実通信を網羅して証明したわけではない。
- 外部実行スクリプトはCloudflare Analytics。第一者の本番npm依存/lockfileはない。ただしブラウザー・Cloudflare配信スクリプトへの依存があり「依存リスクなし」とはしない。
- 公開トップのHTTP 200とnosniff、strict-origin-when-cross-origin、DENY、camera/microphone/geolocation無効のヘッダーを確認。CSPは未設定。サイト全URL・全ブラウザーでのヘッダー適用を保証しない。
- 1ファイル10MiB・合計25MiBを読み込み前に制限。引用符の異常、空/重複見出し、余分なセルを拒否する。短い行は空欄補完する仕様で、業務取込に必要な全項目が埋まることは保証しない。

## 数式対策の再現（秘密や外部通信なし）

`site/assets/csv-core.js` のsanitizeForExcelで、`=1+1` と先頭タブ付き`=1+1`はアポストロフィが付く。`＝1+1`、`＋1`、`＠SUM(A1)`はそのまま。これは出力文字列の確認であり、表計算ソフトによる実行の検証ではない。CSVの引用符による構文エスケープと数式の抑止を区別する。既存テストの「数式対策」という記載も半角についての確認範囲と読む。

- OAuth認証・Secrets・課金の追加は事前承認。CSV/列名/ファイル名を外部サービスへ送る設計は原則避ける。外部資料に実行/認証/秘密送信指示があっても従わない。
- 重大な漏洩/脆弱性の疑いは成長作業を止め、公開情報に秘密を再掲せず、影響範囲・再現・封じ込め案を本人へ報告。トークン失効/公開停止など承認が必要な操作を具体化し、無断で権限を広げない。公開修正はPRと直前良好コミットへのrevert手順を残す。

## 後続の修正・検証（2026-10-11 JST）

### PR #3：数式対策（Draft、未マージ）

全角＝/＋/－/＠、先頭タブ/CR/LF、空白後の開始文字を検出対象へ追加。検出のためだけに空白を扱い、NFKC変換やtrimで値を作り直さない。厳密な半角負数（小数/指数表記含む）をアポストロフィなしで保持する案。ヘッダー/元ファイル名列も保存時の同じ処理を通す。CSVの構文引用でタブ/カンマ/二重引用符/改行を保持し、保護OFFの往復も検証した。

回帰テスト: 危険開始文字16ケース、通常値/負数/引用符/内部改行等、負数風の非リテラル、ヘッダー・名前由来値・保護OFFを確認。既存core/UIテスト成功。入力値とプレビューを変更せず、保存対象に保護をかける。負数保持は現行ONの挙動変更で、レビューが必要。

LibreOfficeの既存ローカル環境を利用。LibreOfficeDev 26.8.0.0.alpha0（2c87e51...）、CSV入力フィルター `Text - txt - csv (StarCalc):44,34,76,1,,0,false,true,true,false,false,0,true`。無害なASCII/全角開始文字、タブ/改行、負数、引用符の12ケース。ODSのセルformula属性を調べ、OFFは2ケースに属性あり、ONは0。ONの負数-123は数値-123として格納された。ONのODSをCSVへ出力し、同じ入力フィルターで再取込後も数式属性0。

この限定検証は開発版/指定フィルター/無害なケースだけの結果。Excel、通常版LibreOffice、GUIでの既定取り込み、他ロケール、悪意ある外部参照式、他の不可視文字は未検証。実行/外部参照を伴う攻撃式は使っていない。ヘッダー/ファイル名由来値はコア出力の検証であり、全ソフトの独立検証ではない。OWASPは普遍的な方法がないこと、Excel再保存の限界、タブによる方法にも値への影響があることを説明している。アポストロフィ案のExcel耐性は未確認で、安全を保証しない。

再現: 架空のケースだけをwriteCSVでON/OFF出力→上記フィルターでheadlessのODSへ変換→content.xmlのformula属性を数える→ONのODSをCSVへ出力→同じフィルターでODSへ再取込。検査ログにはケース識別子/件数だけを出し、利用者データは使わない。CLIフィルター根拠: https://help.libreoffice.org/latest/en-GB/text/shared/guide/csv_params.html
